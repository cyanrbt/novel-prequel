# 候选提升工作流

## 前置条件

1. 候选正文、规划、静态检查、语义审查、盲读和状态结算工件全部存在。
2. 所有工件的输入、输出指纹与当前正式状态一致。
3. 正文没有在最后一次审核后被修改。
4. 用户偏好合同哈希没有变化。

## 提升规则

1. 重新运行所有确定性校验。
2. 拒绝任何缺失、过期、无法解析或证据不成立的审查工件。
3. 同一事务中写入正式章节、章节元数据、状态变化和审核绑定。
4. 任一步骤失败都不得留下部分正式更新。
5. 提升完成后重新检查正式章节连续性和最新状态。

不具备原子写入能力的 Agent 只能提交待提升工件，并返回 `BLOCKED`；其 `artifact.workflow_state` 应标记为 `WAITING_USER`，不得分步修改正式文件。
